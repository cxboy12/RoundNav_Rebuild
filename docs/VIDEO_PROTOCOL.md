# DiPlay JPEG/TCP v1

依据 `D:/workspace/Diplay_project/pc_sender/sender.py` 与 `esp32_receiver/main/dp_protocol.h`、`dp_frame_server.c` 核对。视频 TCP 默认 7000，双方启用 TCP_NODELAY。下表整数全部为无符号小端，魔数为四个 ASCII 字节。

| 方向 | 大小 | 字段（按顺序） |
| --- | ---: | --- |
| ESP32 → 发送端 | 16 B | `DPHI`、屏宽 u16、屏高 u16、JPEG 上限 u32、版本 u16、建议对齐 u16 |
| 发送端 → ESP32 | 16 B + JPEG | `DPJF`、帧号 u32、JPEG 字节数 u32、左上 x u16、左上 y u16、完整 JPEG |
| ESP32 → 发送端 | 20 B | `DPAK`、帧号 u32、状态 u16、就绪队列深度 u16、解码耗时 u32（µs）、整帧耗时 u32（µs） |

- 握手每连接一次，当前固件宣告 466×466、262144 字节、版本 1、对齐 16。发送端帧号从 1 递增，重连重新计数。ACK 可因队列和并行处理而乱序，按帧号匹配。
- TCP 读循环按固定头长度与 JPEG 长度收齐。应用协议没有 UDP 分片、时间戳、协商尺寸字段和 CRC。JPEG 内部头部提供画面尺寸，应用层检查魔数、长度、解析结果和几何边界。
- ACK 状态 0 是提交显示，1 是 JPEG 解析或解码失败，2 是几何错误，3 是长度为零或超限，4 是无空闲接收槽，5 是旧帧被更新帧取代，6 是刷屏传输失败。长度错误或无槽时读掉相应负载。连接收到错误魔数或无法收齐时退出。TCP 接收超时配置为 5 秒。
- 发送端默认最多两帧未确认。ESP32 收齐 JPEG 后才入队，任务优先取最新的排队帧，旧连接的 ACK 通过连接代次隔离。成功 ACK 紧跟最后一块提交，DMA 传输完成及实物显示需另测。
- 固件要求 JPEG 宽高为 8 的倍数、x/y 为偶数、画面落在屏内。旧发送端按握手的 16 像素对齐限制选尺寸。360×360 的主机实板测试收到成功 ACK，最后 8 行的实物画面待专项检查。
- `esp32-direct/` 保留 v1 字段和状态码，握手屏幕尺寸仍为 466×466，将 `align` 改为 8。对齐 8 时，464、448、360 对应的偏移分别为 `(0,0)`、`(8,8)`、`(52,52)`。基准接收器以 16 为对齐值时将 360 向下取整为 352，偏移 `(56,56)`。
- UDP 7001 是独立的发现机制。固件周期广播 ASCII `DIPLAY1 ip=<IPv4> port=<TCP端口> w=<屏宽> h=<屏高> busy=<0或1>`。电脑优先监听广播，失败时尝试本地网段 TCP 探测。直连首版用静态地址。

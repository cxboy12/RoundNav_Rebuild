# RoundNav Direct 实施方案

1. 在 `carwithin-fork/` 保存固定上游版本的开发副本。新增 `RoundNav ESP32` 输出模式，在 `NativeReceiver` 实际视频分发处接入，首版请求 H.264。VideoToolbox 收到连续 access unit，SPS/PPS 更新或输入积压时等下一张 IDR 并请求关键帧。
2. 解码后独立处理最新 CVPixelBuffer，按固定图案核对居中裁切、等比适配、方向和圆外黑色。输出默认 464×464、30 FPS、20 KiB 左右，质量约 0.7 起步。448×448 与 360×360 用于比较画面和性能。检查实际 JPEG SOF 和分量采样因子以及 ESP32 解码。iOS 与 Pillow 质量需要实测匹配。
3. 发送端只保留最新解码图像，最多两帧待 ACK。独立匹配帧号和计时，握手、写入或 ACK 超时后关闭旧连接并重连。独立接收器按 `esp_new_jpeg` 分块模式宣告 8 对齐。基准接收器宣告 16 对齐，选择 360 时会向下取整到 352。两端均可协商 464。
4. 用户确认的微雪 1.75 英寸 AMOLED 使用 466×466 CO5300。固件放在 `esp32-direct/`，沿用 DiPlay Wi-Fi、TCP、RGB565 分块解码和 DMA 架构。画面按面板尺寸居中，坐标向下取偶数。ESP32 AP 默认地址 `192.168.4.1:7000`，SSID 自动生成 `RoundNav-XXXX`。 [微雪开发板资料](https://docs.waveshare.com/ESP32-S3-Touch-AMOLED-1.75)
5. 依次验证主机协议、iOS 构建与签名、JPEG 样本/固件完整接收、DMA 提交、圆屏实际画面。使用公开固定路线做室内模拟。检查 iPhone 关联和地址、局域网访问、蜂窝数据、锁屏、切页、断线重连以及温升。10/15/20/25/30 FPS 每档至少 10 分钟，最终连续 30 分钟。记录源帧率、解码/缩放/编码/发包时间、字节数、接收/丢弃/显示帧率、解码和刷屏耗时、往返、剩余内存。
6. 只有兼容 JPEG 无法达到稳定目标时，才测量 ESP32 软件 H.264 解码和内存压力，再比较原始 Annex B、iOS 转码 H.264 和现成仪表协议。运行时验收仅使用 iPhone 与 ESP32-S3。

构建、主机模拟和设备验收状态见[验证记录](TEST_REPORT.md)。
